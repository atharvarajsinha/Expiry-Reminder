===============================================================================
 HOSTING THE BACKEND ON RENDER
===============================================================================

You create 2 things on Render:

   1. Web Service      - the API (this is the whole backend)
   2. Cron Job         - optional; triggers the daily reminder sweep

There is NO Redis, NO Background Worker and NO Celery Beat. The API runs the
daily reminder check itself on the first request it handles each day, so the
web service alone is a working deployment.

The Cron Job in step 3 is what makes reminders arrive on days you never open
the app. Skip it if you are happy for email to depend on the app being visited.


===============================================================================
 STEP 0 - PUSH THE CODE TO GITHUB
===============================================================================

   cd D:\remind-vahan
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<you>/<repo>.git
   git push -u origin main

Check that .env was NOT uploaded:

   git ls-files | findstr /I ".env"

Only  backend/.env.example  should appear.


===============================================================================
 STEP 1 - WEB SERVICE
===============================================================================

   New +  ->  Web Service  ->  pick your repo

   Name              :  expiry-reminder-api
   Language          :  Python 3
   Branch            :  main
   Root Directory    :  backend
   Region            :  Singapore

   Build Command:
   pip install -r requirements.txt

   Start Command:
   gunicorn config.wsgi:application --bind 0.0.0.0:$PORT --workers 3 --timeout 120 --access-logfile - --error-logfile -

   Health Check Path :  /api/health/

Add the environment variables from step 2, then Deploy.


===============================================================================
 STEP 2 - ENVIRONMENT VARIABLES
===============================================================================

Set these on the web service. If you add the cron job in step 3, the easiest
route is Env Groups -> New Environment Group -> add every line below -> attach
the group to both services.

   DEBUG                 False
   SECRET_KEY            <click Generate>
   JWT_SECRET_KEY        <click Generate>
   CRON_TOKEN            <click Generate>   (only needed for step 3)
   APP_USERNAME          <your login username>
   APP_PASSWORD          <your login password>
   MONGODB_URI           mongodb+srv://USER:PASS@cluster0.xxxx.mongodb.net/?retryWrites=true&w=majority
   MONGODB_DATABASE      expiry_reminder
   BREVO_API_KEY         <your Brevo key>
   BREVO_SENDER_EMAIL    <verified sender in Brevo>
   REMINDER_EMAIL        <where reminders are delivered>
   FRONTEND_URL          https://<your-frontend>.vercel.app
   CORS_ALLOWED_ORIGINS  https://<your-frontend>.vercel.app
   TIME_ZONE             Asia/Kolkata
   AUTH_COOKIE_SECURE    True
   AUTH_COOKIE_SAMESITE  None
   PYTHON_VERSION        3.12.7

AUTH_COOKIE_SECURE and AUTH_COOKIE_SAMESITE are required. Without them the
browser drops the login cookie and every request after login returns 401.

FRONTEND_URL is printed inside every reminder email. Do not leave it as
localhost.

TIME_ZONE decides which calendar day "7 days before" lands on. Get it wrong and
reminders arrive a day early or late.


===============================================================================
 STEP 3 - CRON JOB (optional but recommended)
===============================================================================

Without this, the daily check runs only when someone opens the app. With it,
reminders go out whether or not anyone visits.

   New +  ->  Cron Job  ->  same repo

   Name              :  expiry-reminder-sweep
   Root Directory    :  backend
   Schedule          :  30 3 * * *

   Build Command:
   pip install -r requirements.txt

   Command:
   curl -fsS -X POST -H "X-Cron-Token: $CRON_TOKEN" https://<your-api>.onrender.com/api/reminders/run/

Render cron schedules are in UTC.  30 3 * * *  =  09:00 India time.

The cron job needs only CRON_TOKEN, and it must be the SAME value as the web
service. It calls the API over HTTP, so it needs nothing else.

The sweep is idempotent: a reminder already sent today is not sent again. The
cron ping and someone opening the app on the same morning still produce exactly
one email.


===============================================================================
 STEP 4 - MONGODB ATLAS
===============================================================================

   Atlas -> Network Access -> Add IP Address -> 0.0.0.0/0

Without this, Render cannot reach your database and /api/health/ fails.
URL-encode any special characters in the database password.


===============================================================================
 STEP 5 - BREVO
===============================================================================

   Brevo -> Security -> Authorised IPs -> turn the restriction OFF

Render's outbound IP is not on your allowlist, so leaving this ON makes every
reminder email fail with HTTP 401.

Also confirm BREVO_SENDER_EMAIL appears under Brevo -> Senders as verified.

Leaving the Brevo variables unset is a valid deployment: the app still tracks
everything and shows what is expiring, it just cannot email you.


===============================================================================
 STEP 6 - CHECK IT WORKS
===============================================================================

   curl https://<service>.onrender.com/api/health/

Expect HTTP 200 with the database reported as connected.

   curl "https://<service>.onrender.com/api/health/?sweep=1"

Adds when the daily reminder sweep last ran.

Cron job: click "Trigger Run". The log prints a summary like

   {"success": true, "data": {"triggered_by": "cron", "due": 5, "sent": 5,
    "skipped_already_sent": 0, "failed": 0}}


===============================================================================
 THREE RULES
===============================================================================

 1. NEVER run  python manage.py migrate
    This project uses MongoDB only. DATABASES is empty. migrate will fail.

 2. NEVER run  python manage.py collectstatic
    There is no admin and no whitenoise. It is not needed.

 3. Do NOT try to add a worker or a scheduler process.
    There is no Celery app to run. The daily check lives inside the web
    service (see backend/README.md section 4).

===============================================================================
 IF SOMETHING BREAKS
===============================================================================

 Build fails, "requirements.txt not found"
     Root Directory is not set to  backend

 /api/health/ times out
     Atlas Network Access is missing 0.0.0.0/0

 Health check fails but the site loads
     The path must be  /api/health/  WITH the trailing slash

 401 on every request right after logging in
     AUTH_COOKIE_SECURE=True and AUTH_COOKIE_SAMESITE=None are missing

 CORS error in the browser
     CORS_ALLOWED_ORIGINS must exactly match the frontend URL,
     with https:// and no trailing slash

 Cron job returns 401
     CRON_TOKEN differs between the web service and the cron job, or it is
     unset on the web service (which restricts that route to signed-in users)

 No reminder emails, cron log says "0 due"
     Correct behaviour, not a bug. Nothing expires in exactly 30, 7, 1 or 0
     days today. Check the Reminders screen for the upcoming schedule.

 No reminder emails, log says "failed"
     Open the Reminders screen -> History. A failed row shows the attempt
     count; the next sweep retries it. Usually Brevo Authorised IPs (step 5)
     or a sender address that is not verified.

 Reminders only arrive on days I open the app
     That is the design without step 3. Add the cron job.

 Reminder dates are one day out
     TIME_ZONE is wrong on the web service.
